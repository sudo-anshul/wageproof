## Inspiration

“We corrected both weeks.” A deposit arrives, but which week does it cover, and what remains unresolved? The total alone does not tell the worker what changed or which records to ask for next.

WageProof supports a worker or helper maintaining an ordinary California hourly wage dispute through successive corrections. It preserves sources, compares later evidence with the last reviewed account and prepares a factual update whose premises and unfinished requests remain inspectable. It does not determine entitlement or amend a claim.

## What it does

The fictional demonstration follows a scoped difference of **$140 → $80 → $80**. A $60 gross correction has a $48 net receipt. Later evidence allocates the correction as $25/$35, changing the remaining weekly differences to $55/$25 while the combined $80 stays unchanged. The allocation request is answered; payroll's supporting calculation and reconciliation are still missing.

Source inspection, focused payment decisions, attributed corrections and revision-specific review preserve that distinction. A portable ZIP carries the factual update, detailed supplement, selected originals and extracted text with relative evidence links.

The upgrade carries an open records request into an editable local draft. The user checks the original scope and citations, supplies the intended recipient, saves exact wording and copies or downloads it with its preparation record. Starting text is assembled from the retained action, without a new model call. Saved requests remain bound to their account revision; later evidence makes old drafts inspection-only. Preparing wording neither sends a request nor marks it answered.

Corrected account context also remains authoritative: withdrawing a claim number or recipient leaves it unknown rather than restoring old intake data. Earlier revisions retain their own context. Unreadable saved cases are identified as needing recovery; this is not automatic restoration.

The read-only prepared example lets a reviewer inspect three recorded revisions, six fictional originals, evidence packets and the current request preview without model credentials. Its labels distinguish recorded output and technical review from worker or practitioner approval. A fresh case requires configured analysis access.

## How it was built

Poppler and Tesseract extract local text and labelled OCR. The configured model proposes a typed interpretation with tools disabled. Code checks its schema and exact quote anchors, calculates in integer cents, tracks revisions and review, and assembles exports. Exact quotes establish traceability, not authenticity or correctness. The request editor uses deterministic starting text and ordinary local persistence, not a second letter-writing model.

Stack: React/React DOM, Vite, Ajv, Lucide React, Marked, Node.js, Python, Codex CLI, Poppler and Tesseract; exact dependency versions are recorded in the delivered lockfile. Fonts are Manrope and DM Sans. Earlier recorded inference used configured `gpt-6-astra`, provider `azure`, high reasoning effort; credentials are excluded. Fresh inference is online even though case storage and original files remain local.

OpenAI Codex assisted planning, design, code, tests, review, writing and edit automation. Advisor skills are AI workflows, not human teammates or endorsements. Media uses actual application captures, graphics and captions assembled with Node, Python, Chrome/Playwright and FFmpeg/libx264/ffprobe; edited waits are disclosed. No synthesized voice or music is included. Human narration remains a separate recording step.
