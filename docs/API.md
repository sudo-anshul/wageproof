# Local API contract — upgrade candidate

Base `/api`. JSON responses. Errors `{error:{code,message,details?}}`. Case mutation requests include `expectedVersion` to reject stale edits (HTTP409). Sources/previous revisions are immutable; review belongs to a specific revision.

## Routes

- `GET /health` → `{ok,provider,limits,build}`. Provider is local Codex CLI using the configured model service; inference is not offline. No mock fallback. `build` binds the source/build identity captured at server startup, release label, selected dist/data directories and startup time. Provider availability reports local prerequisites/configuration, not a successful inference.
- `GET /cases` → `{cases:[{id,title,worker,employer,updatedAt,version,sourceCount,revisionCount,reviewed,status}]}`.
- `POST /cases` JSON `{title?,worker?,employer?,stage?:'pending-claim'|'no-claim'|'unknown',claimNumber?,recipient?}` → full CaseRecord.
- `GET /cases/:id` → full CaseRecord.
- `POST /cases/:id/sources` multipart `files` (repeated), optional `kind` (`evidence` or `filed-original`) and `expectedVersion` → full CaseRecord. Send the current version to reject a stale upload. Upload/import only; explicit Analyze starts inference.
- `POST /cases/:id/notes` JSON `{title,text,kind?:'worker-account'|'correction',expectedVersion}` → full CaseRecord. Notes are attributed user text sources.
- `GET /cases/:id/sources/:sourceId` → Source with extracted text.
- `GET /cases/:id/sources/:sourceId/file` → immutable original download.
- `POST /cases/:id/analyze` JSON `{expectedVersion}` → `{job}` with HTTP202. Idempotent while a job is active. Ingests all source text with previous analysis; never a canned answer.
- `GET /jobs/:id` → `{job}`. Job `{id,caseId,status:'queued'|'running'|'completed'|'failed'|'cancelled',stage,message,createdAt,updatedAt,error?,revisionId?,attempts,timings}`. Each bounded attempt retains outcome, validation, model identity and available token usage. Timings separate queue, validation, commit and total processing. Monetary cost stays unknown. Poll about 1.5s; on completion refetch case.
- `POST /jobs/:id/cancel` → `{job}`. Cancellation preserves source/review state. A revision already durably saved wins over a late cancellation; recovery uses its `createdByJobId` receipt. This is not a full power-loss transaction guarantee. CaseRecord.lastJobId retains the latest job so an interrupted or failed outcome is visible after reload.
- `POST /cases/:id/revisions` JSON `{analysis,reason,expectedVersion}` → full CaseRecord; creates a corrected proposal from a user-edited analysis, never mutates old versions. Requires an existing proposed revision and a reason. Changed facts receive a new attributed correction source and exact citations; source and revision save together. Unchanged forms create no new record, and citation-only rewrites are rejected. Domain validation + calculation runs. UI forms may copy analysis and edit fields per domain contract.
- `POST /cases/:id/review` JSON `{revisionId,expectedVersion,note?}` → full CaseRecord; marks precisely that current version reviewed, including explicitly retained uncertainty. New sources mark stale until analyzed/reviewed.
- `GET /cases/:id/export?revision=:revisionId&format=zip&sources=:sourceIds` → a portable packet from the selected frozen revision: short update, detailed supplement, evidence index, exact text companions and selected originals. Omit `sources` for all cited originals; `sources=` explicitly includes none. Comma-separated IDs must belong to that revision. Omitted sources remain listed. Literal spans and original hashes are checked before packaging. The ZIP limit is 128 MiB.
- `GET /cases/:id/export?revision=:revisionId&format=preview&asset=update.html&sources=:sourceIds` → the same packet renderer with safe, revision/selection-bound local navigation. Only exact generated members can be served. Original assets download.
- `GET /cases/:id/export?revision=:revisionId&format=md` → current/default Markdown supplement. `format=html` returns printable escaped HTML. Draft/unreviewed status is visible. Export never means filed/sent.
- `GET /examples` → `{examples:[{id,title,description,phases:[{id,label,fileCount}]}]}`.
- `POST /examples/:id/start` → full CaseRecord; imports phase0 only, no precomputed analysis. User invokes Analyze.
- `POST /cases/:id/example-phase` JSON `{phaseId,expectedVersion}` → full CaseRecord; imports actual raw files for that demonstration phase, no precomputed response.

## Records

CaseRecord: `{id,title,context:{worker,employer,stage,claimNumber,recipient},version,createdAt,updatedAt,sources:Source[],revisions:Revision[],currentRevisionId,reviewedRevisionId,reviewedSourceDigest,activeJobId,lastJobId?,exampleId?,importedPhases:[],activity:[]}`.

Source: `{id,name,mime,kind,sha256,size,createdAt,text,lineCount,extraction:{method,warnings:[]}}`. Source IDs and original storage filenames are generated by the server, not user paths. Extracted text is shown verbatim with line numbers. Quotes are checked against that text, not against unseen OCR truth.

Revision: `{id,number,createdAt,reason,sourceDigest,sourceIds,origin:'model'|'user',analysis,calculation,changes,sinceReviewed,sincePrevious,createdByJobId?,supplement,validation:{warnings:[]},review:{status:'reviewed',at,note}|null,model:AttemptMetadata|null}`. `analysis` and derived `calculation` follow `docs/DOMAIN-CONTRACT.md` and domain/index.mjs. The server owns version/digest/review status. A source-only update can stale a review without changing money. `sinceReviewed` names the last review available when the revision was created; `sincePrevious` names the adjacent proposal. Unreviewed intermediate drafts do not shift the primary review baseline.

Limits declared before evaluation: English text/Markdown/CSV, text PDFs, PNG/JPEG via local OCR. Up to12 files per request,12MiB/file,40MiB/request,200k extracted characters per case,40 PDF pages. Image-bearing pages in otherwise text-readable PDFs receive labelled same-page OCR (at most 12 image-bearing pages; 120 seconds per PDF); image-only PDFs still require page images or a transcription. Required extraction failure rejects the import rather than accepting partial text. Encrypted/broken/unsupported files return a clear error; OCR output is inspectable and may need correction. Initial rules support only explicit simple hourly California assumptions within the domain contract. Unsupported legal scope still permits a factual account/update without an invented calculation. No arbitrary URL ingestion, external claim submission or official-form filling.

## Fixed recorded example (lexhack-finish-1)

`GET /api/prepared-example` returns availability and recorded-fictional provenance. `GET /api/cases/prepared-example` returns the fixed read-only case with three original recorded revisions. Existing source/original/history/export reads work for this alias. Exported HTML, Markdown and ZIP carry recorded-example and technical-review labels. Every non-GET request under this case alias is rejected with HTTP403 `PREPARED_EXAMPLE_READ_ONLY`; there is no generic case-import endpoint. A missing/corrupt bundle returns HTTP503 `PREPARED_EXAMPLE_UNAVAILABLE`. Reading the example does not create a case, job, review or model call.

## Local unsent request drafts (lexhack-requests-2)

- `GET /cases/:id/request-drafts?revision=:id` returns selected revision metadata, current preparation eligibility/reason, eligible open or partly answered ordinary/payroll records requests with deterministic starting fields and immutable basis, plus all saved drafts with current/stale reasons.
- `POST /cases/:id/request-drafts` accepts `{expectedVersion,revisionId,actionId,draftId?,recipient,subject,body}`. It creates a new draft or edits the named current draft under the case lock, returning `{case,draft}`. It increments the case/draft versions and activity only: no source, calculation, revision, job, action status or review changes. Recipient may be empty; subject/body are required. Limits: recipient300/subject240 single-line characters, body12,000 characters,50 saved drafts. Control characters and single-line separators are rejected. Existing cases default to an empty draft collection.
- `GET /cases/:id/request-drafts/export?draftId=:id&draftVersion=:number` returns `{text,filename,draftId,draftVersion}`. Add `format=txt` for identical plain-text attachment bytes. Requires the exact saved draft version and current revision/source/action basis with no active analysis. Stale drafts remain readable in the index but cannot export as current. Unsaved edits are not accepted by this endpoint.
- Prepared example GET export uses `actionId` and `revision` instead of a saved draft. It returns an explicitly fictional, immutable seed preview; the global non-GET rejection still applies. Historical prepared revisions cannot seed a current request.

A request draft contains `id`, integer `version`, `actionId`, `revisionId`, `sourceDigest`, `actionFingerprint`, immutable `basis` (revision/action scope and citations), recipient/subject/body and timestamps. A listing adds `current` and `reason`. Saving requires optimistic case version matching. Export checks saved draft version separately so another view's changed wording cannot silently replace what was reviewed. User-authored request text is not automatically source-verified. The text export includes an unsent designation and a separate preparation record; there is no delivery endpoint.

Selected analysis context is authoritative for party/routing values and claim status. Null/unknown stays unknown; initial intake is used only before an analysis exists. Historical context and stored earlier caches are preserved; outward supplements regenerate from the selected revision.
