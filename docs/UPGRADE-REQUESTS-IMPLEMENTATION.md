# WageProof request and context upgrade

`lexhack-requests-2` extends the preserved `lexhack-finish-1` release with a completed local evidence-request workflow. It retains the wage-correction problem, model/prompt, integer accounting, source records, prior evaluation and accepted cobalt interface.

## What changed

A current open or partly answered ordinary/payroll records request now has a focused editor. It keeps the original scope and citations beside recipient, subject and body fields. Starting wording includes the retained action verbatim and is explicitly presented for editing. A saved request is an unsent local artifact; it does not add evidence, settle a question, run a model or review the wage account.

Drafts store a revision/source/action basis separately from editable text. Case-version comparison prevents concurrent silent overwrites. Every copy or download fetches the exact saved draft version and rechecks freshness. New sources, a new revision, a changed/closed action or active analysis block use as a current draft. Earlier saved wording remains inspectable. A current eligible request can start a separate draft; no stale draft is silently rewritten. The prepared fictional example offers an immutable, labelled preview with no save path.

Selected analysis context now controls outward party names, recipient, claim number and claim status. Clearing a fact retains unknown instead of reviving intake data. Before any analysis, intake remains available. Historical revisions/caches are preserved; supplements regenerate from their selected revision. The full correction editor now exposes claim status. Saved-case rows explain `Needs recovery`, show the server's preservation message and omit unknown counts/time.

## Scope and verification boundaries

The core demonstrations and existing public evaluation remain the same known synthetic cases. The preserved strong ordinary workflow also passed. This upgrade introduces no model evaluation, private-key inspection, accuracy percentage, measured human savings or legal validation. Request text is editable and is not automatically verified for truth or legal sufficiency. It is never sent by WageProof.

Context regression checks exercise actual corrections, review, standalone/portable exports and historical unknowns. Request tests exercise persistence, saved-version export, concurrent updates, stale source/revision/action/job boundaries, input validation, limits and prepared read-only behavior. Browser checks cover desktop/narrow views, source inspection, failure recovery and keyboard behavior. Exact results and hashes are supplied in the separately delivered release/setup receipts; passing source tests alone is not a hosted deployment claim.

A Unicode-control validation failure was retained and repaired after independent API reproduction. The initial test-only wrong prepared alias was also retained. Browser harness failures are recorded separately from actual product defects. No unfavorable result is turned into fresh evaluation evidence.

The request editor does not provide arbitrary case import, automatic recovery, backup/restore, automated outreach or legal form filing. The case storage remains local with existing filesystem protections. No dependency, provider, spending or publication scope was expanded.
