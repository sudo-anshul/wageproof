# Prepare and keep a request

WageProof can turn a current unresolved records request into wording you can edit, save locally and carry away. Saving a draft does not send it, answer the request, add evidence or review the wage account.

This guide accompanies `lexhack-requests-2`. The release handoff identifies the exact checked source, build and verification scope.

## Make a draft

1. Open the current account. Under **Move the case forward**, choose **Prepare request** on an eligible open or partly answered records request. If sources have changed, analyze the current records first. Finish or cancel an active analysis before preparing a draft.
2. Read **Why this request remains open** and inspect its cited sources. The starting wording includes the current action's exact scope. Edit it into the request you want to make; it is not a newly generated letter.
3. Check **To**, **Subject** and **Request wording**. To starts blank and is optional. Confirm the person or payroll contact yourself; this recipient can differ from the deputy receiving a case update. WageProof does not supply an email address or deadline.
4. Select **Save request draft**. Wait for the saved confirmation. Your draft appears under **Saved request drafts** and can be reopened after reloading the case. A save error leaves your text in the editor; unsaved wording is not durable storage.
5. Use **Copy request** or **Download text**. Both use the exact saved version, so save changes before exporting. The text includes the unsent request followed by a separate preparation record: the account revision, original request scope and cited excerpts. Read the complete text before using it elsewhere. Copying and downloading do not communicate with the recipient.

Subject and body are required. Limits are 300 characters for To, 240 for Subject, 12,000 for the body and 50 saved drafts per case. To and Subject use a single line. The limit produces an explicit error; this version has no draft deletion or merging workflow.

## When the account changes

Drafts belong to the revision, sources and action used to prepare them. Earlier drafts remain inspectable but cannot be exported as current after that basis changes. Open the current account and choose **Start a current draft** if the request is still eligible. If new evidence has answered it, the old wording remains history rather than an active request.

Conflicting saves do not silently replace another view's successful save. The editor retains your typed text and explains whether you can retry against an unchanged basis or need to reopen the newer draft. Leaving an edited dialog asks whether to keep editing or discard unsaved changes.

## Inspect the fictional example

The prepared example offers **Preview request example** on its current eligible request. Its fields are read-only; copy/download produces the exact fictional preview, clearly labelled as recorded-example material. It creates no saved request and makes no model call. Historical revisions remain available for inspection, but new requests start from the current account.

## Routing, recovery and scope

The selected account controls the worker, employer, claim number, recipient and claim status shown in its outputs. Withdrawing a detail leaves it unknown; old intake values do not silently fill it back in. Historical revisions retain their own recorded context.

A **Needs recovery** case means the saved account cannot be read. Unknown counts and dates do not mean the case is empty. This upgrade explains the condition; it does not automatically repair or restore the case. Keep the existing data directory intact. The evidence ZIP is a recipient packet, not a complete backup.

Request wording is user-editable and is not certified for factual accuracy, legal sufficiency or delivery. Fresh analysis still uses the configured model service; request preparation itself requires no new inference. See the [main guide](../README.md) for setup, supported inputs and calculation limits.
