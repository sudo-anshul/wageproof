# Vercel deployment

**Live:** https://wageproof-theta.vercel.app

Verified production deployment: `dpl_4LexaEfbUbZcHP5A5vbhtxmskoe8`.

Vercel serves WageProof's existing **read-only fictional walkthrough**. Visitors can inspect six original records, compare the three recorded accounts, preview a current records request and download revision-specific evidence packets. The established local application remains available from the same source.

The hosted entry and diagnostics identify the public demo. There is no upload, case creation, editing, new model analysis or personal-case persistence on Vercel. Requests other than GET/HEAD are refused; only the fixed bundled example can be read. No Codex credentials or local case directory are deployed. The adapter verifies the fixture manifest, original hashes, source anchors and retained calculations before serving it. A missing or altered fixture fails closed.

This is the hosting adaptation of `lexhack-requests-2`. The prepared case retains its recorded `upgrade-candidate-4` origin; hosting it does not constitute a new model run or a new human review. Prior evaluation limits and the creator-human-pitch dependency remain unchanged.

## Reproduce

Use Node 22.12 or newer in the 22.x series. The dependency lockfile is unchanged apart from the declared Node engine; no new runtime dependency was added.

```sh
npm ci
npm test
npm run build:vercel
vercel link
vercel deploy --prod
```

`vercel.json` chooses the hosted build and includes the fixed fictional fixture in the Node function. The frontend uses the explicit build flag `VITE_WAGEPROOF_HOSTED=true`; ordinary `npm run build` retains the editable local interface. A dedicated `api/demo.mjs` handler exposes the inspection/export routes. The original local HTTP server is not started in Vercel.

The deployed function needs no environment secrets or external database. The existing Vercel Hobby account is used without purchasing a plan or model credits. The attempted GitHub integration did not connect; CLI deployments work independently. There is no automatic GitHub deployment configured by this work.

For full local uploads, edits and fresh inference, follow the README. Moving that workflow into a shared cloud service would require durable case storage, isolation/authentication, a supported extraction/worker runtime and model-service configuration; this release does not claim those capabilities.

## Verification

The public deployment passed 48 anonymous HTTP and artifact checks on 25 September 2026. The existing 124 tests passed and the final adapter passed 11 dedicated tests. Desktop (1280 px) and narrow (390 px) browser inspection covered entry, source inspection, revision history, request preview, source omissions, ZIP download and embedded document preview across local and public builds. Checks cover hosted JSON routes, recorded accounting, original bytes, history, source selection/omissions, request text, ZIP integrity, route rejection, missing-fixture failure and rendered desktop/narrow interaction states. No fresh model evaluation or end-user study is implied.

The initial deployment exposed an extra route parameter generated by Vercel and failed public API checks. Renaming the route capture fixed it; the successful deployment above supersedes that attempt. The first Python verification attempt also encountered a local CA configuration issue, resolved by using the system CA bundle without disabling TLS verification. These failures and final receipts are retained in the local HPDLC workspace. No model request ran during this deployment.
